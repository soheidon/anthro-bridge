# 1-2. Anthro Bridge 専用 Workspace Rule 実装プラン

## Context

1-1 で `mcp-server`（`plan` ツール）が完成し、実APIスモーク・リリースビルドまで成功した。しかし現状は、Antigravity に毎回長い教示文（「関連コードを調査し、plan を1回呼んで…」）を書かないと DeepSeek プランナーが使われない。

これを自動化するため、Anthro Bridge プロジェクト専用の **Antigravity Workspace Rule** を1つ作る。発火モードは **Model Decision**（モデルが description を読んで「非自明な実装タスク」だと判断したときだけ適用）。`always_on` は「1語の文言変更」まで DeepSeek を呼ぶ恐れがあるため不採用。

## 調査で判明した Antigravity Rule の保存形式（実装前調査）

公式ドキュメントでは「Rule は単なる Markdown ファイル」としか書かれておらず、frontmatter の具体的なキー名・値は掲載されていない。そこで実在するルールファイルとパーサ実装を調査した：

| 出典 | 判明事項 |
|---|---|
| Google 公式ドキュメント | `.agents/rules/`（ワークスペース）、`~/.gemini/GEMINI.md`（グローバル）。4モード: Manual / Always On / Model Decision / Glob。Model Decision は自然言語 description で適用判断 |
| Mete Atamel（Google DPE）ブログ | `.agents/rules/`、`.agents/workflows/`、`~/.gemini/config/global_workflows/`。trigger 値 `always_on` を agent 出力で確認 |
| 実ルールファイル（`anoopsg/agent_rules` 等） | frontmatter は `trigger:` + `description:` の2キー。**`name` キーは無い**（識別はファイル名） |
| パーサ実装（Herald.Ai.Skills / agentsync / agent-rules-tool） | `trigger` の値として `always_on` / `model_decision` / `glob` / `manual` を処理 |

**結論**：`trigger: model_decision` + `description:` が現行 Antigravity の Model Decision 形式として最有力。この調査結果に基づき `.agents/rules/deepseek-planner.md` を作成した。

> **注意（残存する不確実性）**：一部リポジトリでは旧形式らしき `trigger: auto` / `trigger: always` が見られた（`model_decision` → `auto` への変換ツールも存在）。Rule が発火しない場合は、ご利用の Antigravity で Workspace Rule を1つ UI から作成して実際の保存形式を確認し、`trigger` の値を合わせること。

## 決定事項

| 決定 | 選択 | 理由 |
|---|---|---|
| 発火モード | Model Decision（`trigger: model_decision`） | trivial な変更まで DeepSeek を呼ばない |
| 識別 | ファイル名 `deepseek-planner.md`（`name` キー不使用） | 実ファイル・公式で確認 |
| 配置 | `.agents/rules/`（git ルート直下） | Antigravity 仕様。既存 `.agents/` なし → 新規 |
| MCP 参照 | `anthro-bridge/plan` | 1-1 登録時のサーバー名 `anthro-bridge` と一致 |

## Rule 全文（正本）

`.agents/rules/deepseek-planner.md`：

```markdown
---
trigger: model_decision
description: Use for implementation, debugging, architectural changes, or multi-file code changes where an external implementation plan would be useful. Do not use for trivial text-only edits.
---

# DeepSeek Planner Rule

For non-trivial implementation tasks in this repository:

1. First inspect the repository yourself and identify the files and code relevant to the task.
2. Summarize only the context necessary for implementation planning.
3. Call the `anthro-bridge/plan` MCP tool exactly once with:
   - the user's task;
   - the relevant repository context;
   - important constraints.
4. Use the returned DeepSeek plan as the basis for implementation.
5. Perform file edits, builds, and tests yourself.
6. Do not call `anthro-bridge/plan` again unless the implementation encounters a major unresolved problem.
7. Do not ask the user to repeat this workflow.
8. Do not use the planner for trivial tasks such as a one-word text change unless planning would materially help.
```

## 段階的移行

- **現段階**：MCP 登録 + Workspace Rule（本プラン）。
- **将来**：Anthro Bridge 用 Antigravity Plugin として、`mcp_config.json` + `rules/` + `skills/` を1パッケージ化。Plugin 化時は本 Rule を `rules/deepseek-planner.md` として同梱する。

## 検証

1. `.agents/rules/deepseek-planner.md` が git ルートに存在し、frontmatter（`trigger` + `description`）が正しいこと（目視）。
2. **中程度のタスクで切り分け検証**（最初から「MCP管理UI」のような大きいタスクにしない）：
   - 例：「既存の小さな設定項目を1つ追加する」
   - 確認：Model Decision が発火 → `anthro-bridge/plan` が**ちょうど1回**呼ばれる → DeepSeek の計画が返る → そのまま実装まで進む。
3. trivial な変更（例:1語の文言変更）では planner が呼ばれない（Model Decision が適用を回避する）ことを確認。
4. 切り分け検証が通った後に、本命タスク（例:「MCP管理UIを追加してください」）へ進む。

## 守る制約

- コミットしない（ユーザー指示があるまで。SPEC 24 準拠）。
- `.agents/` は今回新規に作成するルート直下ディレクトリ。Antigravity Rule は定義上 git ルート（`.agents/rules/`）に置く必要があるため、SPEC 24 の「mcp-server/ 配下に限定」の例外としてユーザー明示指示により正当化される。
- `gui/` / `gui/src-tauri/` / 既存設定・プロバイダ挙動には触れない。
