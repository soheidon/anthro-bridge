# Claude Code + Ollama Local

Anthro Bridge can route Claude Code to a locally running Ollama model while leaving Claude Desktop and MCP on their existing cloud providers.

---

## Architecture

```text
Claude Code
     │
     │ Anthro Bridge Claude Code marker (X-Anthro-Bridge-Client: claude-code)
     ▼
Anthro Bridge Gateway
     │
     ├─ Gateway route (`active_route = "gateway"`) ──→ Global cloud provider (DeepSeek / MiMo / OpenRouter / etc.)
     │
     └─ Ollama route  (`active_route = "ollama"`)  ──→ http://127.0.0.1:11434 (`/v1/messages`)
                                                          │
                                                          ▼
                                                     Local model
```

Ollama Local is intentionally **Claude Code-only**. It does not replace the global cloud provider used by Claude Desktop or Anthro Bridge MCP tools.

---

## Requirements

1. **Anthro Bridge** installed and running.
2. **Ollama** installed and running on your local machine.
3. At least one model pulled in Ollama (e.g. `gemma4:latest`, `llama3.3:70b`, `qwen2.5-coder:32b`), or an arbitrary custom model tag.
4. Claude Code launched using the launch command generated by Anthro Bridge.

---

## Configure Ollama Local

Open Anthro Bridge:
1. Navigate to **Settings > API Key**.
2. Scroll to the **Ollama Local** settings card below the API Keys table.

### Main Settings Row

- **Model**: Dropdown showing discovered Ollama models plus custom model entry.
- **Refresh (`🔄 Refresh`)**: Queries the local Ollama `/api/tags` endpoint to populate installed models.
- **Thinking**: Choose **Normal (Disabled)** or **Thinking (Enabled)**.
- **Show on Dashboard**: Checkbox controlling whether Ollama Local appears as a selectable card on the Dashboard.

### Advanced Settings (`▸ Advanced Settings`)

- **Endpoint**: Base URL for Ollama. Default is `http://127.0.0.1:11434`.
- **Vision**: Enable or disable image base64 input for multimodal local models (default: disabled).
- **Context Window**: Optional explicit context capacity in tokens (e.g. `131072`).
- **No API Key Required**: Local loopback Ollama instances do not require an API key.

---

## Model Discovery & Refresh

Clicking **Refresh (`🔄 Refresh`)** sends a request to:

```http
GET http://127.0.0.1:11434/api/tags
```

### Security & Preservation Rules

- **Loopback-only**: Only loopback addresses (`127.0.0.1`, `localhost`, `[::1]`) are queried.
- **Non-blocking errors**: If Ollama is not running or the request times out (2-second bounded timeout), an inline notice is shown, and the saved model configuration is **never cleared**.
- **Custom model preservation**: If your saved model is not present in the returned list, it remains selected in the dropdown.
- **Custom model tags**: Select `+ Custom model tag...` to manually enter any model identifier.

---

## Select Ollama on the Dashboard

1. Enable **Show on Dashboard** in Settings.
2. Go to the **Dashboard**.
3. Click the **Ollama Local** tile:
   - Sets `claude_code.active_route = "ollama"`.
   - Global `active_provider` remains **unchanged** (e.g. `deepseek`).
   - The Ollama tile highlights as **Claude Code Active**.
4. To return to the cloud provider route:
   - Click any cloud provider tile (e.g. DeepSeek or MiMo) on the Dashboard.
   - Claude Code automatically resets to `claude_code.active_route = "gateway"`.

## Thinking Semantics

Anthro Bridge translates your Thinking selection into the Anthropic-compatible format supported by Ollama:

- **Normal**:
  ```json
  "thinking": { "type": "disabled" }
  ```
- **Thinking**:
  ```json
  "thinking": { "type": "enabled" }
  ```

*Note: Ollama Local does not expose reasoning effort levels (Low/Medium/High/Max).*

---

## Context Window & Auto-Compaction

- `context_window` is **optional**.
- When specified, Anthro Bridge uses it for Claude Code context management and auto-compaction threshold calculations.
- When omitted (`null`), Anthro Bridge does not assume an arbitrary context size and uses default auto-compaction rules.

---

## Claude Code Identification Marker

Anthro Bridge's generated Claude Code launch command injects an internal marker via `ANTHROPIC_CUSTOM_HEADERS`:

```text
X-Anthro-Bridge-Client: claude-code
```

- **Header normalization**: Anthro Bridge normalizes the header case-insensitively, replaces duplicate or stale marker variants, and preserves unrelated user custom headers.
- **Stripped before upstream**: Anthro Bridge consumes this marker locally for routing decisions and strips it before forwarding requests upstream.

---

## Client Isolation

| Client | Route Selector | Target |
| :--- | :--- | :--- |
| **Claude Code** | `claude_code.active_route` (`"gateway"` or `"ollama"`) | Selected Dashboard provider / Ollama Local |
| **Claude Desktop** | `active_provider` (Global cloud provider) | Cloud provider gateway (DeepSeek, MiMo, OpenRouter, etc.) |
| **Antigravity MCP** | `mcp.provider` / `mcp.profile_id` | Dedicated MCP planner & reviewer provider |

This design guarantees that switching Claude Code to Ollama Local will **never disrupt** Claude Desktop or Antigravity MCP workflows.

## Troubleshooting

### Refresh cannot find Ollama
1. Confirm Ollama is running in the background or terminal:
   ```powershell
   ollama list
   ```
2. Verify the endpoint in Advanced Settings is `http://127.0.0.1:11434`.

### My saved model is not listed
Anthro Bridge preserves your saved model even if `/api/tags` does not return it. You can also select `+ Custom model tag...` to manually enter the model tag.

### Claude Code still uses the cloud provider
1. Check the Dashboard and confirm the **Ollama Local** tile is active.
2. Ensure you started Claude Code using the launch command generated by Anthro Bridge (`Copy Claude Code launch command`).

### Claude Desktop still uses the cloud provider
This is the intended behavior. Ollama Local is Claude Code-only.
